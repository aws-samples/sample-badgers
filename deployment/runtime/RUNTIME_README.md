# 🐳 AgentCore Runtime Container

Docker container running the Strands agent. Full uses WebSocket streaming;
Headless disables WebSockets and accepts authenticated versioned agent requests
that submit to the private durable workflow runner. This branch is a private,
untagged 6.0 candidate; see the [Release Guide](../../RELEASE_GUIDE.md).

## Choose the runtime mode

| Mode | Reader goal | Start here |
| --- | --- | --- |
| Full | Operate the browser-facing, streaming agent | [Quick Start](#quick-start) and [UI guide](../../ui/UI_README.md) |
| Headless | Integrate authenticated, durable document requests | [Headless request mode](#headless-request-mode) and [Headless product guide](../../badgers-headless/README.md) |
| Maintainer | Change the image, dependencies, or agent behavior | [Build options](#build-options) and [Customization](#customization) |

## Contents

```
runtime/
├── Dockerfile.websocket      # Container definition (WebSocket streaming)
├── build_and_push_websocket.sh # Build and push to ECR
├── requirements.txt          # Python dependencies
└── agent/
    ├── __init__.py
    └── main-websocket.py     # Strands entry point; WebSocket or Headless mode
```

## Quick Start

> [!IMPORTANT]
> The ECR stack must be deployed before building the container.

```bash
# Build and push (requires ECR stack deployed first)
./build_and_push_websocket.sh

# Then deploy Runtime stack
cd .. && DEPLOYMENT_ID=dev uv run cdk deploy "BADGERS-RuntimeWebSocket-${STACK_SUFFIX}"
```

## Environment Variables

Set by Runtime stack:

| Variable                         | Description                               |
| -------------------------------- | ----------------------------------------- |
| `AWS_DEFAULT_REGION`             | AWS region                                |
| `GATEWAY_URL`                    | MCP Gateway endpoint                      |
| `COGNITO_CREDENTIALS_SECRET_ARN` | Secrets Manager ARN for OAuth credentials |
| `AGENTCORE_MEMORY_ID`            | Memory ID for session persistence         |
| `WEBSOCKET_ENABLED`              | `true` for Full; `false` for Headless     |
| `CONFIG_BUCKET_NAME` / `CONFIG_PREFIX` | SHA-pinned configuration release location |
| `WORKFLOW_STATE_MACHINE_ARN`     | Private Headless operation runner, when enabled |
| `HEADLESS_AUTH_MODE` / `HEADLESS_AUTHORIZED_CLIENT_ID` | Headless JWT validation configuration |
| `ROUTING_WORKFLOWS_BY_TYPE_JSON` | Release-pinned source MIME type to workflow mapping |

The configuration prefix is a deployment-private S3 release generated by Step
3; it is not a Git release tag. The runtime must use the configured prefix
rather than accepting a caller-provided configuration location.

## Headless request mode

In Headless mode, the runtime validates the dedicated Cognito client token and
derives the operation owner from its `client_id`. A
`badgers-agent-request/v1` request supplies a tenant-scoped source URI accepted
by its selected workflow, an instruction, session ID, and `auto` or `manual`
routing mode. The starter workflow accepts PDF, PNG, and JPEG. A deployment
that explicitly selects the native DOCX or PPTX processor and matching template
also accepts that source type. The runtime creates a durable operation and
returns pointer metadata; it does not return native specialist artifacts inline.

The default runner catalog contains the PDF/image starter workflow. Selecting
`docx_processor` or `pptx_processor` and the matching reviewed workflow
template adds native DOCX/PPTX support to that deployment. When a caller omits
`workflow_id`, the runtime consults the release-pinned MIME-type mapping; an
explicit workflow ID always wins. External BADGERS Gateway MCP tools are not
yet published.

## Build Options

```bash
# Build with custom tag
./build_and_push_websocket.sh v1.0.0

# Manual build
docker build -f Dockerfile.websocket --platform linux/arm64 -t pdf-analysis-agent .
```

## Customization

### Modify Agent Behavior
Edit `agent/main-websocket.py` to change:
- System prompt
- Model selection
- Tool handling
- Session management

### Add Dependencies
1. Add to `requirements.txt`
2. Rebuild and push: `./build_and_push_websocket.sh`
3. Redeploy Runtime stack

## Troubleshooting

```bash
# View Runtime logs
aws logs tail /aws/bedrock-agentcore/runtimes/<runtime_id> --follow

# Check container locally
docker run -p 8080:8080 pdf-analysis-agent

# Verify ECR image
aws ecr describe-images --repository-name pdf-analysis-agent-<deployment_id>
```
